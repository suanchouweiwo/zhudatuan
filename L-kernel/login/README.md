# 登录系统接入

Ethan 在 2026-10-04 选择登录系统作为完整业务核心接入 LK 的第一项。本记录说明当前实现边界，不新增认证协议、规则或发布条件。

| 共用登录核心 | 实例与适配层 |
| --- | --- |
| 登录名与手机号归一化、原密码验证实现 | 实例身份密钥、KMS 和现有凭据查询 |
| 密码或短信登录、会员身份选择及会话签发编排 | 入口域名、Realm、目标应用与会员组织解析 |
| state、nonce、PKCE 与登录目标规则 | HTTP 字段、请求头、Cookie 与现有返回格式 |
| 登录意图、会话事件与票据签发的调用顺序 | 原数据库事务、SQL、短信挑战事实与事件写入 |
| 回跳签名及原会话有效期计算 | 实例签名密钥、数据库记录的回跳地址和有效时间 |

核心入口为 `@shop/l-kernel/login`，实现在 `src/login`。现有 `SessionTicketOperations` 的登录创建操作调用 `LoginSystem`；`PgLoginStore` 使用该操作原有的事务连接，并复用 `SmsLogin`、`RealmAccount`、`PgAuthTicket` 与会员适配。旧模型、密码策略与签名路径转发到 LK 的唯一实现。

原密码格式和参数、短信消费时机、会员选择结果、会话和登录票据返回格式保持原样。多会员选择结果仍先返回候选；选定会员后才消费短信挑战。会话创建、登录意图消费、事件写入、签票与可选直接换票继续属于同一事务。

L0 或后续实例加载同一实现，再绑定各自的域名、Realm、数据库和外部资源。账号、凭据、Owner、角色、手机号、会员和会话事实仍保存在实例数据库中；迁入代码不会初始化或复制这些记录。

本批接入登录与会话票据主线。注册邀请、手机号绑定、密码重置与微信身份的完整业务编排仍位于现有身份模块；其使用的已迁密码、身份归一化和签名实现通过旧入口复用 LK。权限与治理继续由现有 AccessPipeline 提供，不增加另一套 Owner 或授权解析。
