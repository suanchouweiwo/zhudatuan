这是 `zdt-next` 中共用 L-kernel 的逐步迁入目录，不是第二套节点模型或新的公共契约。现有 L0～L11 节点、关系与 Realm 事实仍以原 `@shop/config/sfl-node-kernel` 入口及现有数据库实现为准；该入口中的纯等级和 MB 登记解析已转发到本内核的唯一实现。

Ethan 在 2026-10-04 明确：LK 是整套系统的共用核心；L0 加载核心形成完整实例，并可生成 L1 或复用同一核心建立另一套 L0。各实例绑定自己的节点清单、Realm、数据库、资源与业务画像。OP 的治理身份仍沿现有实现处理。

迁入按业务能力逐项进行。旧接口在对应能力迁入时接到共用实现，旧实现随后收口；不能同时留下两份写入事实。HTTP、SQL、外部服务和部署配置属于适配层，不因共用而搬进纯业务核心。首个能力见 [会员迁入清单](member/README.md)。

本目录已作为私有工作区包 `@shop/l-kernel` 接入构建。已实际迁入的纯规则及尚未继承的能力见 [MB 会员内核继承实况](member/INHERITANCE_STATUS.md)。商城会员目录和详情 SQL 只在原 `member` 模块的适配层完成切割切薄，尚未迁入本目录；这不改运行时路由，也不代表节点数据库或整套会员能力已迁入。

登录系统是本次选定的业务迁入项，核心与实例的实际边界见 [登录系统接入](login/README.md)。密码与短信登录的业务编排由 LK 提供，HTTP、SQL 事务、外部服务和实例配置由现有身份适配层绑定。

节点差异日后可由简短 JSON 描述，但节点、Realm 与数据库的真实绑定必须沿用现有权威数据；本目录不复制一套虚构的 L0/L1/H6 节点清单。
